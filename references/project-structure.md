## 1. Reference layout

Root-level source folders, no `src/` [code]. Native `ios/` and `android/` folders are generated by
`expo prebuild` and git-ignored (Continuous Native Generation) [config: .gitignore]; native customisation goes
through Expo config plugins.

```
<root>/
├── app/                         # expo-router routes: screens and layouts only
│   ├── _layout.jsx              # root: error boundary, Redux Provider, initialisation, providers, root Stack
│   ├── +not-found.jsx
│   ├── (auth)/                  # route group for sign-in flows
│   │   ├── _layout.jsx          # Stack with screenOptions={{ headerShown: false }}
│   │   ├── login/{_layout.jsx,index.jsx,forgot.jsx}
│   │   └── profile-select.jsx
│   └── (app)/                   # route group for the main app (guests allowed, sections gated in layouts)
│       ├── _layout.jsx          # registers Stack.Screen entries + mounts global modals
│       ├── (tabs)/{_layout.jsx,index.jsx,lessons.jsx,settings.jsx,leaderboard/}
│       ├── [courseId].jsx       # dynamic route
│       ├── child-details/[id].jsx
│       └── edit-profile.jsx     # kebab-case route files
├── components/
│   ├── Common/                  # app-wide primitives (ThemedText, ThemedSafeAreaView, Header, ModalContainer, ...)
│   ├── Form/                    # form fields and auth forms
│   ├── SDKs/                    # headless <Sdk>Initialize components mounted once in the root layout
│   ├── Home/                    # one PascalCase folder per screen or domain
│   │   ├── Continue/
│   │   │   ├── Continue.jsx     # section entry, same name as its folder
│   │   │   └── components/      # children private to this section
│   │   │       └── ProgressBar.jsx
│   │   └── PaginationDots.jsx   # simple domain component, no folder needed
│   ├── Button.jsx               # a few generic components live at the top level
│   └── AppErrorBoundary.jsx
├── features/                    # Redux Toolkit, one camelCase folder per domain
│   ├── api/apiSlice.js          # the only createApi() instance: base query, auth, tagTypes
│   ├── auth/{authApi.js,authSlice.js,loginSlice.js,registrationSlice.js}
│   └── leaderboard/{leaderboardApi.js,leaderboardSlice.js}
├── hooks/                       # use<Name>.jsx - one hook per file, default export
├── utils/                       # camelCase.js pure helpers and thin service wrappers (storage, analytics)
├── context/                     # imperative global UI services, one folder each:
│   └── alert/{AlertProvider.jsx,AlertContent.jsx,AlertService.js}
├── providers/AppProviders.jsx   # composes every React provider in one place
├── store/{store.js,middleware.js}
├── constants/{constants.js,styles.js}   # UPPER_SNAKE constants; COLORS / SHADOWS tokens
├── i18n/{index.js,resources.js,language.js,locales/<lang>/<namespace>.json}
├── data/                        # static datasets (countries, avatars, tutorial copy)
├── assets/{icons,images,svgs,gifs,audio}/   # camelCase file names; SVGs import as components
├── styles/                      # raw CSS used only inside WebViews
├── plugins/with<Name>.js        # Expo config plugins
├── scripts/                     # dev/CI tooling (e2e runner, seeding)
├── __tests__/                   # Jest tests mirroring the source tree
├── test-utils/helpers.js        # shared test helpers
├── .maestro/                    # Maestro e2e flows; shared steps in common/, login/
└── app.json · eas.json · babel.config.js · metro.config.js · tailwind.config.js · global.css
    eslint.config.js · .prettierrc · jest.setup.js · package.json (+ jest block) · package-lock.json
```

## 2. Placement table

| You need | Put it in | Name | Notes |
|---|---|---|---|
| A screen | `app/<group>/<route>.jsx` | kebab-case | Register it in the group's `_layout.jsx` when that layout lists screens explicitly [code] |
| A nested stack | `app/<group>/<route>/_layout.jsx` + `index.jsx` | | Sub-screens beside `index.jsx` |
| A dynamic route | `app/<group>/[param].jsx` or `<route>/[id].jsx` | camelCase param | Read with `useLocalSearchParams()` |
| A tab | `app/(app)/(tabs)/<tab>.jsx` + entry in `(tabs)/_layout.jsx` | | Title from `t()`, set `tabBarAccessibilityLabel` |
| UI used across domains | `components/Common/<Name>.jsx` | PascalCase | Folder form `Common/<Name>/<Name>.jsx` once it has children |
| UI for one screen/domain | `components/<Domain>/<Name>.jsx` | PascalCase | `<Domain>` is the screen or feature name |
| A child used by one parent only | `components/<Domain>/<Section>/components/<Child>.jsx` | PascalCase | Keeps the domain folder flat [code] |
| Variants of the same UI | `components/<Domain>/<group>/v1/`, `v2/` ... | | Seen for A/B-tested paywalls [code] |
| A form field | `components/Form/<Name>.jsx` | | |
| Third-party SDK setup | `components/SDKs/<Sdk>Initialize.jsx` | | Returns `null`, mounted once in the root layout |
| A custom hook | `hooks/use<Name>.js` | camelCase after `use` | A hook used by one component may sit beside it [code: 1 case] |
| REST endpoints | `features/<domain>/<domain>Api.js` | | `apiSlice.injectEndpoints`; add tag types to `apiSlice` |
| Global client state | `features/<domain>/<domain>Slice.js` | | Register in `store/store.js` under the same key |
| Reactions to actions (persist, logout cleanup) | `store/middleware.js` | `<purpose>Middleware` | |
| A pure helper | `utils/<topic>.js` (or the shared `utils/utils.js`) | camelCase | Named exports |
| A wrapper around storage/analytics/device APIs | `utils/<service>.js` | | e.g. `secureStore.js`, `asyncStore.js`, `analytics.js` |
| A constant, limit, or device-size flag | `constants/constants.js` | `UPPER_SNAKE_CASE` | |
| Colours and shadows | `constants/styles.js` **and** `tailwind.config.js` theme | `COLORS`, `SHADOWS` | Keep both in sync |
| Imperative global UI (alert, toast, limit modal) | `context/<name>/` trio | `<Name>Provider.jsx`, `<Name>Content.jsx`, `<Name>Service.js` | Mount the provider in `AppProviders.jsx` |
| A new React provider | `providers/AppProviders.jsx` | | Never wrap providers inside screens |
| Copy text | `i18n/locales/<lang>/<namespace>.json` | snake_case keys | Namespaces: `main` (default), `common`, `pages`, `auth` |
| Static data | `data/<name>.js` | camelCase | |
| An icon or image | `assets/<type>/<camelCase>.<ext>` | | SVGs imported as React components |
| An Expo config plugin | `plugins/with<Name>.js` | | Referenced from `app.json` |
| A unit/component test | `__tests__/<same path as source>/<Name>.test.js` | | `.test.js` even when it contains JSX [code] |
| An e2e flow | `.maestro/<flowName>.yml`; shared steps in `.maestro/common/` | camelCase | Targets elements by `testID` |

## 3. Naming rules

| Item | Rule | Evidence |
|---|---|---|
| Route files and folders | kebab-case (`edit-profile.jsx`, `child-details/`); `(group)`; `[param]`; `_layout.jsx`; `index.jsx`; `+not-found.jsx` | [code] all route files |
| Component files | PascalCase, file name = default export name | [code] |
| Component folders | PascalCase domain/section folders; lowercase only for `components/` (private children), `common/`, and version folders `v1/`, `v2/` | [code], with exceptions in §7 |
| Section entry | `<Section>/<Section>.jsx` (not `index.jsx`) | [code] |
| Hooks | `use<Name>`, default export, file named after the hook | [code] 20/20 |
| Redux files | `<domain>Api.js`, `<domain>Slice.js`; API object `const <domain>Api`; slice `const <domain>Slice` | [code] |
| Slice `name` | equals the store key and the file prefix | [inferred] (one copy-paste violation in reference) |
| Generated RTK hooks | `useGet<Thing>Query`, `use<Verb><Thing>Mutation` | [code] |
| Endpoint names | queries `get<Thing>`/`getSingle<Thing>`; mutations `add`/`update`/`delete`/verb + noun | [code] |
| Utils, constants, data, i18n files | camelCase | [code] |
| Context service trio | `<Name>Provider.jsx`, `<Name>Content.jsx`, `<Name>Service.js` | [code] |
| SDK initialisers | `<Sdk>Initialize.jsx` | [code] |
| Config plugins | `with<Name>.js` | [code] |
| Assets | camelCase (`backIcon.svg`, `courseLoadingIcon.svg`) | [code] |
| Tests | `<SourceName>.test.js`, same relative path under `__tests__/` | [code] |
| i18n keys | snake_case, nested by screen/feature (`home.continue.button.start`) | [code] 549/555 keys |
| `testID` values | kebab-case, dynamic suffix for list items (`list-item-${id}`) | [code] |
| Analytics events and params | snake_case (`lesson_start`, `source_screen`) | [code] |

## 4. Adding a feature end-to-end

Example: an "Achievements" screen backed by an API. Skip steps the feature doesn't need.

1. **Endpoints** - `features/achievement/achievementApi.js` with `injectEndpoints`; add `"Achievement"` to
   `tagTypes` in `features/api/apiSlice.js`; `providesTags` on queries, `invalidatesTags` on mutations.
2. **Client state** (only for state the server does not own, e.g. a selected filter) -
   `features/achievement/achievementSlice.js`; register `achievement: achievementReducer` in `store/store.js`.
3. **Hook** - `hooks/useAchievements.js` combining the query, selectors, and derived data. Put multi-step
   logic (mutations + analytics + navigation) here rather than in components.
4. **Components** - `components/Achievements/AchievementList/AchievementList.jsx` with private children in
   `components/Achievements/AchievementList/components/`. Reuse `components/Common/*` primitives.
5. **Screen** - `app/(app)/achievements.jsx` composing the components; register
   `<Stack.Screen name="achievements" />` in `app/(app)/_layout.jsx` if that layout lists screens.
6. **Entry point** - navigate with `router.push("/achievements")` from an existing screen or tab.
7. **Copy** - add `achievements.*` keys to every locale (`pages` namespace for screen copy, `common` for shared
   buttons/labels/alerts).
8. **Analytics** (if the product tracks it) - add the event to the event map in the analytics wrapper and call
   it with snake_case params.
9. **Tests** - `__tests__/components/Achievements/...`, `__tests__/hooks/useAchievements.test.js`,
   `__tests__/features/achievement/achievementSlice.test.js`.
10. **E2E hooks** - `testID`s on new interactive elements; add or extend a Maestro flow when the feature is on a
    critical path.
11. **Verify** - SKILL.md step 8.

## 5. Bootstrapping a new project

Create folders as files need them; an empty folder skeleton adds nothing. Confirm with the user before adding
large pieces (Redux, i18n, e2e) to a tiny app.

### Expo / React Native (closest to the reference)

1. Ask whether the project should be JavaScript (the reference) or TypeScript, unless the user said.
2. Create the app with the current `create-expo-app` template that includes expo-router (check
   `npx create-expo-app@latest --help` and the Expo docs, because templates change between SDKs), then remove
   the template's example screens and components.
3. Add tooling: ESLint + Prettier from `assets/` (see development-rules.md §1-2), Jest (`jest-expo` preset,
   `jest.setup.js`), NativeWind (`babel.config.js`, `metro.config.js`, `tailwind.config.js`, `global.css`).
4. Add the base files in this order, each only when the first feature needs it:
   `app/_layout.jsx` → `providers/AppProviders.jsx` → `components/Common/ThemedText.jsx` and
   `ThemedSafeAreaView.jsx` → `store/store.js` + `features/api/apiSlice.js` → `i18n/` →
   `constants/constants.js` + `constants/styles.js` → `utils/cn.js` → `__tests__/`.
5. Keep `ios/` and `android/` out of git; add native changes through config plugins in `plugins/`.
6. Add `.env.example` listing variable names (development-rules.md §5).

### React web (Vite)

Keep the same role folders under the template's `src/` (`src/components`, `src/features`, `src/hooks`,
`src/utils`, `src/constants`, `src/i18n`, `src/store`), put routes in `src/routes/` (or `src/pages/` if the router
setup suggests it) using kebab-case file names for route modules, Tailwind for styling, Vitest or Jest for tests.
Place tests in `src/__tests__/` mirroring the tree, unless the user prefers colocated tests.

### Next.js (App Router)

Routes stay in `app/` with Next's reserved names (`page.jsx`, `layout.jsx`, `loading.jsx`, `error.jsx`); route
segment folders are kebab-case. Keep `components/`, `features/`, `hooks/`, `utils/`, `constants/`, `i18n/` beside
`app/` (or under `src/` if the project uses it).

### Backend (Node server)

Use the backend profile instead: `backend/project-structure.md`. Don't project this frontend layout onto a
server.

## 6. Applying the structure to an existing project

1. Map existing folders to roles (e.g. `src/screens` → screens, `src/redux/slices` → slices,
   `src/api` → endpoints). Use the existing locations; don't move files.
2. Put new code in the existing folder for its role. If no folder exists for that role, create the reference
   name under the project's source root (`src/` if it has one).
3. Don't introduce a second structure next to the first (no `features/` beside an existing `src/redux/`).
4. Keep existing file-name casing in each folder if it is consistent there, even if it differs from the table above.
5. Path aliases: if `jsconfig.json`/`tsconfig.json` define aliases (`@/`), use them the way existing files do. The
   reference uses relative imports only [code: 1,330 relative imports, 0 aliases].

## 7. Inconsistencies in the reference and the rule for new code

| Area | What the reference contains | Rule for new code |
|---|---|---|
| Component folder names | Mostly PascalCase; also `leaderboardDetails/` (camelCase), `Hint&ExplanationDetails/` (contains `&`), `subscriptionVariants/` | PascalCase, letters and digits only; lowercase only for `components/`, `common/`, `v1/`-style folders |
| Slice file extension | `settingsSlice.jsx` (contains no JSX) | `.js` |
| Hook extension | 19 `.jsx`, 1 `.js`, none render JSX | `.js` in new projects; match the folder majority in existing ones |
| Slice name | `leaderboardSlice` uses `name: "interaction"`, colliding with the real interaction slice's action types | Slice `name` equals the store key |
| Layout components | 3 `export default function` layouts (two needed an empty JSDoc stub to satisfy lint) | Arrow function + `export default` at the end |
| Import extensions | 4 files import with `.jsx`/`.js` | Extensionless relative imports |
| i18n key style | 6 camelCase keys (`tabBar`, `bottomSheet`, ...) | snake_case |
| `testID` style | 12 camelCase IDs (`upgradeToPro`, `showPassword`) and a few mixed-case ones among 195 | kebab-case |
| JSX in `.js` files | 2 non-component modules (`data/`, `utils/`) return JSX from `.js` files | `.jsx` whenever a file contains JSX |
| Test imports | Some tests interleave imports with `jest.mock()` and leave specifiers unsorted | Same import rules as source; `jest.mock` calls after the import block |
| Locale parity | Secondary locale missing ~29 keys present in English | Add every new key to every locale in the same change |
| File size | 11 files disable `max-lines` | Split instead; disable only with a comment explaining why |
