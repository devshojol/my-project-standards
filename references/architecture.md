## 2. Layers and dependency direction

```
app/            routes: read params + store, call hooks, compose components, navigate
  │
components/     presentational + section components; may call hooks
  │
hooks/          orchestration: RTK Query hooks + selectors + dispatch + analytics + navigation
  │
features/       <domain>Api.js (server state)   <domain>Slice.js (client state)
  │                    │                                │
  │             features/api/apiSlice.js         store/store.js + store/middleware.js
  │             (base query, auth, tags)         (configureStore, persistence, logout cleanup)
  │
utils/          pure helpers + wrappers for storage, analytics, device APIs
constants/      sizes, limits, tokens - imported by every layer
i18n/           initialised once at startup; components use useTranslation()
context/        imperative global UI services (alert/limit modals) callable from any layer
providers/      single composition point for React providers
```

Rules [code + inferred]:

- Imports flow downward. `utils/`, `constants/` and `features/` never import from `components/`, `hooks/` or `app/`.
- Components may read the store and call RTK Query hooks directly for simple reads; anything with several
  steps (mutation + analytics + navigation + persistence) belongs in a hook.
- A service wrapper may read the store when it needs app-wide context (the analytics wrapper reads global
  params from the store). Keep such imports one-way to avoid cycles.
- Screens contain no business logic beyond wiring; they should be readable top to bottom in under a minute.

## 3. App bootstrap

The root layout (`app/_layout.jsx`) establishes, in order [code]:

1. Monitoring initialisation at module level (`Sentry.init({ ..., enabled: !__DEV__ })`), splash screen held.
2. `Sentry.ErrorBoundary` with a friendly fallback component that can reset.
3. Redux `<Provider store={store}>`.
4. Headless SDK initialiser components (`<XInitialize />`) mounted as siblings of the app content.
5. An `AppContent` component that calls an initialiser hook which, in parallel: loads fonts, initialises i18n,
   restores tokens/user from secure storage and cached state from AsyncStorage, then fetches the server
   context. It returns `{ loading, contextError, retryInitialization }`.
6. Splash hidden when loading ends; an error/retry screen if critical data could not be restored (never continue
   on default data that could later overwrite real server data).
7. `<AppProviders>` (gesture root → bottom-sheet provider → keyboard provider → alert services → safe area).
8. Root `Stack` with the `(app)` and `(auth)` groups, header hidden, no animation between groups.
9. Screen-view analytics fired from a `usePathname()` effect; app-open tracking on cold start and when returning to foreground.

For a new project, keep the same shape and leave out the pieces the app doesn't need.

## 4. Routing and navigation

- Route groups separate signed-in/guest app (`(app)`) and auth flows (`(auth)`); a `(tabs)` group inside `(app)`
  holds the tab screens. [code]
- Group layouts register their screens (`<Stack.Screen name="..." />`) and mount group-wide modals. [code]
- Guests can use the app; sections that need an account are gated in their `_layout.jsx` by rendering a
  "not logged in" modal instead of the stack. [code]
- Tabs use a custom `TabBar` component and translated titles; a tab whose content is a stack sets
  `popToTopOnBlur`. [code]
- Dynamic routes for entities (`[courseId].jsx`, `child-details/[id].jsx`); query strings for flags (`?skip=3`). [code]
- Deep links (attribution SDK callbacks) are handled once at the root and routed by a `handleRedirect` util. [code]

## 5. State architecture

| Kind of state | Where it lives | Persistence |
|---|---|---|
| Server data (lists, profiles, leaderboards) | RTK Query cache via `apiSlice` | None (refetch), invalidated with tags |
| Session (user, access/refresh tokens) | `auth` slice | `expo-secure-store` |
| Offline-first user data (profile, progress, guest trial) | dedicated slices | AsyncStorage, written by middleware after each update action |
| Settings (sound, vibration) | `settings` slice | |
| Cross-screen UI state (selected filter, modal flags, query params) | small domain slices | |
| Ephemeral UI state (inputs, open/close, local loading) | `useState` in the component or hook | |
| Global imperative UI (alerts, limit modals) | `context/<name>/` service trio | |
| Static data | `data/*.js`, `constants/*.js` | Bundled |

Logout is handled once, in middleware: clear secure storage, reset slices, sign out of SDKs, navigate home. [code]

**Imperative UI service pattern** [code]: `<Name>Service.js` holds a module-level function reference with
`set<Name>Fn(fn)` and `show<Name>(data)`; `<Name>Provider.jsx` renders children plus `<Name>Content />` and
registers its `show` function in an effect; any module (including non-React code) can call `show<Name>()`.

## 6. Networking

- One `fetchBaseQuery` wrapped by `baseQueryWithReauth` [code]:
  - `prepareHeaders` adds `Authorization: Bearer <token>` from the store (unless the request set its own), plus
    client metadata headers (app version, device model) and an acting-as header for child profiles.
  - 401 (except a wrong-password error code) → dispatch `logout()`.
  - 403 → single-flight token refresh shared by concurrent requests; retry once on success, logout on failure;
    rotated refresh tokens are persisted to secure storage immediately.
  - 429 → returned to the caller unchanged.
- These status-code semantics are a contract with the reference's backend. In another project, mirror the
  structure (single base query, central auth handling, single-flight refresh) but use that backend's contract. [inferred]
- Base URL: the reference switches environments by editing a constant - don't copy that. Read it from
  `process.env.EXPO_PUBLIC_API_URL` (or the framework's public env prefix). [inferred]
- Responses use an envelope `{ success, data, message, code }`. [code]

## 7. Cross-cutting services

- **Analytics**: one wrapper (`handleEvent(name, params)`) maps internal names to provider event names, adds
  global params (user type, grade, pro status), and fans out to providers. Event and param names are
  snake_case. Components never call analytics SDKs directly. [code]
- **Monitoring**: Sentry initialised once, disabled in development, user identity set/cleared when the auth
  user changes, app wrapped with `Sentry.wrap`. [code]
- **i18n**: initialised asynchronously before first render; language stored in AsyncStorage; `changeLanguage`
  helper persists the choice. [code]
- **Responsive design**: three breakpoints (< 720 phone, 720-1023 medium tablet, >= 1024 large tablet) shared by
  Tailwind (`md`, `lg`), the `IS_*` constants, and the scale-ratio hook (1 / 1.35 / 1.75). [config + code]
- **Native configuration**: Expo config plugins in `plugins/` instead of editing generated native projects;
  `patch-package` (run in `prepare`) for unavoidable dependency fixes. [code]
- **Privacy**: the app targets children - tracking SDKs are configured to minimise data collection. Ask about
  the audience before adding any tracking SDK to a new project. [code + inferred]

## 8. Porting the architecture to other stacks

| Reference element | React web (Vite) | Next.js (App Router) |
|---|---|---|
| `app/` routes | `src/routes` with react-router | `app/` (`page.jsx`, `layout.jsx`) |
| `components/<Domain>/...` | same | same; mark client components with `"use client"` only where needed |
| `hooks/` | same | client hooks only |
| `features/*Api.js` (RTK Query) | same | client components only; keep server fetching if the project uses it |
| `features/*Slice.js` | same (if Redux is used) | store provider in a client `providers.jsx` |
| NativeWind + StyleSheet | Tailwind CSS | Tailwind CSS |
| SecureStore | httpOnly cookies set by the backend; never put tokens in `localStorage` [inferred] | same |
| AsyncStorage | `localStorage` for non-sensitive cache | same (client only) |
| `testID` | `data-testid` | `data-testid` |
| `EXPO_PUBLIC_*` | `VITE_*` | `NEXT_PUBLIC_*` |
| Maestro | Playwright/Cypress, if the project has one | same |
| Portable to every stack | naming, import order, Prettier settings, JSDoc, async/error handling, i18n discipline, file-size limit, tests mirroring source | ← |

Node servers (and Next.js route handlers that hold real business logic) follow the backend profile:
`backend/architecture.md`.

When a framework's own convention conflicts with a row above, the framework wins; record the decision in the report.

## 9. Dependency policy

- Prefer what is already installed; then the reference's choice from §1; then the framework's recommended library.
- One library per concern (one state library, one data-fetching approach, one styling system, one date approach).
- Native modules in Expo: `npx expo install <pkg>` so versions match the SDK. [code: SDK-pinned `~` versions]
- Expo packages use `~` ranges (SDK-locked); most other packages use `^`; a few native libraries are pinned
  exactly where upgrades are risky. [code]
- Keep `expo.doctor.reactNativeDirectoryCheck.exclude` in package.json updated when adding packages that
  `expo-doctor` would flag but are known to work. [code]
- Every new dependency is mentioned in the final report with the reason it was needed.
